# 智能家居软件前端设计

日期：2026-07-07

## 背景

项目要求完成智能家居系统的软件部分，后端已提供 Flask REST API，包含用户认证、设备控制、YOLO 识别预留接口、门禁访问记录接口。比赛题目要求 GUI 能展示必要信息，支持数据统计分析，并通过界面远程控制灯、空调等设备。

前端采用“总览大屏 + 管理后台能力”的混合方向：第一屏突出家庭状态总览，便于答辩演示；下方或侧栏提供设备、门禁、识别、用户管理等完整操作能力。

## 目标

1. 提供可直接运行的 Web GUI，集成到现有 Flask 项目中。
2. 支持登录、注册、登出和会话状态保持。
3. 展示智能家居总览，包括设备数量、开启状态、门禁记录、识别状态等。
4. 支持设备列表、筛选、新增、编辑、删除、开关控制。
5. 支持门禁识别演示：上传图片或选择模拟识别对象，调用 YOLO 检测与门禁验证接口，并展示访问记录。
6. 支持数据统计与分析：按设备状态、房间、类型、门禁记录生成前端统计视图。
7. 管理员账号 `admin` 登录时展示用户管理入口，支持用户列表、编辑和删除。

## 范围

### 包含

- Flask 模板前端页面：`templates/index.html`。
- 静态资源：`static/css/app.css`、`static/js/app.js`。
- 必要的 Flask 路由调整：让 `/` 返回前端页面，保留 API 路由不变；前端通过 `/api/...` 调用后端。
- 兼容现有 Session 鉴权，`fetch` 请求使用 `credentials: "same-origin"`。
- 如果数据库为空，前端提供“快速初始化演示设备”按钮，通过现有设备创建接口批量创建设备。

### 不包含

- 不实现真实 YOLO 模型推理。现有后端接口是预留接口，前端只调用并展示返回结果。
- 不接入真实硬件传感器。温度、亮度历史若后端没有接口，将作为演示卡片和前端模拟趋势展示。
- 不重写后端鉴权、数据库结构或硬件通信协议。

## 架构

前端作为 Flask 单页应用运行：

- `/`：返回 GUI 页面。
- `/api/auth/*`：登录、注册、登出、用户管理。
- `/api/device/*`：设备查询和控制。
- `/api/yolo/*`：识别、门禁验证、访问记录。

页面加载后先请求 `/` 或直接尝试受保护接口判断登录态。未登录展示认证页面；登录后进入主界面。

## 页面结构

### 认证页

- 登录卡片：用户名、密码、登录按钮。
- 注册卡片：用户名、姓名、密码、确认密码、注册按钮。
- 默认提示可使用 `admin / 123456`，但不强制写死账号。

### 主界面

- 顶部栏：系统名称、当前用户、刷新、退出登录。
- 总览区：设备总数、开启设备数、门禁记录数、最近识别结果。
- 设备控制区：房间和类型筛选、设备卡片、开关切换、新增/编辑/删除设备。
- 门禁识别区：图片上传转 Base64 调用 `/api/yolo/detect`；选择检测对象和置信度调用 `/api/yolo/access/verify`。
- 统计分析区：按房间/类型/开关状态聚合设备，展示简单图表；展示门禁记录时间线。
- 用户管理区：仅当当前用户名为 `admin` 时显示。

## 数据流

1. 用户登录成功后保存当前用户对象到前端状态。
2. 前端并行加载设备列表、设备类型、房间、门禁记录；管理员额外加载用户列表。
3. 设备开关、编辑、删除成功后重新拉取设备数据并刷新统计。
4. 门禁验证成功后重新拉取访问记录。
5. 401 响应统一处理为回到登录视图。

## 错误处理

- API 请求失败时显示顶部 toast。
- 表单必填项在前端先校验。
- 登录失效或未登录访问返回 401 时清空前端状态并回到认证页。
- 删除用户、删除设备前使用确认弹窗。

## 视觉设计

- 使用深浅对比的现代控制台风格，但避免单一深蓝或大面积紫色。
- 主色使用青绿色代表在线和安全，辅以琥珀色表示告警/待处理，灰白背景保证信息可读。
- 设备卡片使用小圆角、图标、状态徽标、开关控件。
- 第一屏保持演示友好：核心状态在无需滚动时可见。

## 验证

- 启动 Flask 后访问 `/`，确认页面正常渲染。
- 注册或登录后，确认设备列表、门禁记录可加载。
- 创建设备、切换状态、编辑、删除设备均能通过后端 API 生效。
- 门禁验证能产生访问记录。
- 管理员账号能看到用户管理，普通用户不能看到。

## 决策

推荐方案为“总览大屏 + 管理后台能力”混合方案。它最适合比赛项目：展示效果强，同时覆盖后端已有接口和题目要求的软件功能。
